# 有源 youyuan

> 问渠那得清如许，为有源头活水来。—— 朱熹《观书有感》

把各平台的图文、视频内容聚合到一起，**绕过平台的商业推荐机制**。

## 它解决什么

平台的推荐算法按你的历史决定**给你哪一条**。你越点，它越窄。

有源换了个做法：

> **个性化只发生在「配额」层，不发生在「内容」层。**

内容由群体信号（分区、排行、热度）决定，你的偏好只决定**每个分区给几条**。
配额由你**显式调整**，绝不根据点击行为自动学习 —— 一旦学习，就等于把推荐
算法重新造了一遍。

## 架构

客户端/服务端分离。后端跑在常开的机器上，客户端只负责界面和播放。

```
┌─ 常开的机器 ────────────┐          ┌─ Flutter 客户端 ─┐
│  Python 后端             │          │  Linux 桌面       │
│   · 定时抓取分区内容      │◄── HTTP ─►│  Android（同一套）│
│   · 视频池（带 TTL）      │  只发元数据└──────────────────┘
│   · 采样（分块 + 二次）    │                  │
└─────────────────────────┘                  │ 直连 CDN
                                             ▼
                                    视频流不经过后端
```

**视频流不经过后端**：客户端自己取播放地址，于是后端带宽为零，且客户端拿到的
是离自己最近的 CDN 节点。

## 目录

```
fetch.py       网络层    模拟浏览器抓取，不含任何站点知识
bilibili.py    站点层    B 站页面 / 接口解析
sampling.py    采样      从池子里挑这一轮展示哪几条（纯函数）
store.py       持久状态  视频池 + 已展示记录 + 设置
server.py      后端      FastAPI，把上面四样接起来
client/        Flutter 客户端
```

分层是单向的：`sampling` 不认识网络也不认识存储（时间、随机源、已展示记录都由
调用方传进去），`store` 认识网络但不认识 HTTP，`server` 把三者接起来。

## 跑起来

后端需要 Python 3.12+ 和 [uv](https://docs.astral.sh/uv/)：

```bash
uv run server.py           # 起在 0.0.0.0:8000（首次会自动装依赖）
```

第一次启动会花十几秒抓内容建池子，之后每 30 分钟刷一轮。

客户端需要 Flutter SDK：

```bash
cd client
dart analyze
flutter build linux --debug
./build/linux/x64/debug/bundle/youyuan_client
```
